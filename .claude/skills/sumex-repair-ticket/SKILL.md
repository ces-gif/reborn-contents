# SUMEX 장비 수리 접수

병원은 "빨리 고쳐달라", 본사는 "부품이 없다". 영업 담당이 중간에서 압박받는
구조다. **대장이 유일한 방어 수단이다.**

## 절대 규칙

1. **병원에 완료 날짜를 먼저 약속하지 않는다.**
   "접수하고 예상 일정 확인해서 바로 회신드리겠습니다"로 끊는다.
   날짜를 말하는 순간 책임이 넘어온다.
2. **현장에서 임의 분해하지 않는다.** 우리 역할은 증상을 좁혀서 정확히 접수하는 것.
3. **비인가 수리업체를 거치지 않는다.** 정품 서비스 채널로만 접수한다.

## 절차

### 1. 증상을 정확한 단어로 받아 적는다

"화면이 이상하다"가 아니라 "가로 줄이 간헐적으로 뜬다". 고객의 말 그대로 기록한다.

### 2. 에러코드가 있으면 먼저 해석한다

| 코드 | 의미 | 현장 1차 조치 |
|---|---|---|
| E01 | Video Error | 전원 재기동 |
| E02 | Console Overheating | 통풍구·랙 공간 확인 후 재기동 |
| E03 | Software Mismatch | 전원 재기동, LCD 우측 하단 버전 캡처 |
| **E05** | Unauthorized Component | **정품 케이블 여부 확인**, 커넥터 청결·핀 상태 |

> E05 는 비정품 케이블에서 자주 뜬다. ProCare(정품 서비스 계약)의 가치를
> 설명할 최적의 순간이다.

증상별 원인 추적 순서는 `SUMEX/knowledge/60-트러블슈팅.md` 참조.
**김서림이 보이면 즉시 사용 중단**하고 누수 검사로 접수한다.

### 3. 교차 시험을 시킨다

다른 카메라 헤드 / 다른 CCU 에서도 재현되는가. 이 한 줄이 "No Problem Found"
반송을 막는다.

### 4. 접수한다

```bash
cd SUMEX && export PYTHONPATH=src
python3 -m sumex.cli repair open 서울적십자 "1788 CCU" "전원이 간헐적으로 꺼짐"
```

명령이 **본사에 함께 물어야 할 것**을 출력한다. 반드시 세 가지를 같이 묻는다.

1. 예상 소요 기간
2. 부품 재고 유무
3. **대체 장비(loaner) 대여 가능 여부**

> 병원이 화내는 실제 이유는 수리 지연이 아니라 **수술 일정이 밀리는 것**이다.
> 대차 장비만 나가면 불만이 크게 줄어든다.

### 5. 진행을 갱신한다

```bash
python3 -m sumex.cli repair update --id R26-001 --set \
    status=본사확인중 vendor_reply="부품 재고 확인 중" eta=2026-09-05 \
    loaner="대차 1대 가능" parts_in_stock=확인중
python3 -m sumex.cli repair list --open-only
```

상태값: `접수` `본사확인중` `부품대기` `수리중` `완료` `수리불가`

### 6. 병원이 묻기 전에 먼저 연락한다

`sumex today` 가 **회신 없이 3일 이상 지난 건**을 자동으로 띄운다.
결론이 안 나도 중간 상황을 알린다. 지연 자체보다 '연락이 없는 것'에 불만이 쌓인다.

특히 **서울적십자병원**은 응대 속도가 관건인 계정이다.

### 7. 서면으로 종결한다

원인·조치·재발 방지책을 서면 회신한다. 구두 종결하지 않는다.
필요하면 재교육(인서비스), 특히 세척·멸균 절차.
