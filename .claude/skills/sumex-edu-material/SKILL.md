# SUMEX 교육자료 제작

## 먼저 읽을 것

`SUMEX/knowledge/` 가 이미 완성된 교육자료 본체다. **새로 쓰기 전에 반드시 읽는다.**

| 파일 | 내용 |
|---|---|
| `00-온보딩-로드맵.md` | 90일 커리큘럼, 읽는 순서 |
| `10-산업-기초.md` | 산업 지도, 재료·고정 원리, 시장·경쟁사, 인허가·급여 |
| `20-해부학-어깨.md` | 어깨 복합체 50분 강의안 (슬라이드 단위로 구성됨) |
| `30-제품-심층.md` | 1788·System 9·CORE 2·Zip·ICONIX·T7 |
| `40-서류-업무-총람.md` | 병원별 서류 규칙 |
| `50-영업-플레이북.md` | 의사결정 구조, 경쟁 대응, 컴플라이언스 |
| `60-트러블슈팅.md` | 에러코드, 증상 추적, 클레임 SOP |
| `70-용어집.md` / `80-자가점검.md` | 용어, 문제은행 |

기계가 읽는 사실 데이터는 `SUMEX/data/products.yaml` (`sumex product ICONIX`).

## 원칙 — 이 자료들이 지키고 있는 것

1. **해부학 → 질환 → 수술 → 제품**의 순서로 연결한다.
   제품 이름을 먼저 말하는 자료는 현장에서 안 쓰인다.
2. **의학 / 공학 / 영업** 세 관점으로 같은 구조를 반복한다.
   신입이 새 제품을 만날 때 스스로 이 세 칸을 채우는 훈련이 되게 한다.
3. **"왜"를 먼저 답한다.** "좋습니다"가 아니라 "재료가 X이고 구조가 Y라서
   Z라는 물리적 이점이 있습니다".
4. **실전 한 문장**을 반드시 넣는다. 집도의 앞에서 그대로 말할 수 있는 문장.
5. **수치는 조건과 함께.** "봉합사보다 8배 강함"은 어떤 조건에서인지 같이 말한다.
6. 각 단락 끝에 **"영업 관점"** 을 붙인다. 지식이 매출로 연결되는 지점.

## 새 강의안을 만들 때

### 구조

```
① 왜 이걸 배우는가        (매출·대화·수술과 어떻게 연결되는지)
② 개념                   (해부 또는 원리)
③ 질환 / 고장             (무엇이 잘못되나)
④ 수술 / 조치             (어떻게 해결하나)
⑤ 제품 매핑표             ★ 인쇄해서 나눠줄 결론 슬라이드
⑥ 집도의와의 대화 예시     (롤플레이용)
⑦ 3분 요약 + 자가점검 10문항
```

`20-해부학-어깨.md` 가 이 구조의 완성형이다. 새 부위(무릎·척추·고관절·복강경)를
만들 때 그 형식을 따른다.

### 분량

- 50분 강의 = 슬라이드 약 25장 = `##` 헤딩 25개
- 실습을 최소 2곳 넣는다 (직접 해보게 하는 것)
- 발표자 노트에 해당하는 내용은 인용문(`>`)으로 단다

### 출력

- 기본은 **마크다운**으로 `SUMEX/knowledge/` 에 저장한다
- 슬라이드가 필요하면 `pptx` 스킬로 변환
- 배포용 웹 페이지가 필요하면 Artifact 로 발행 —
  단, **대외비 사내 교육용**이므로 사용자에게 공유 범위를 먼저 확인한다

## 사실 확인

교육자료의 신뢰도가 곧 영업사원의 신뢰도다.

- 품번·사양은 `data/products.yaml` 과 대조한다
- 시장 수치는 **출처와 기준연도**를 함께 쓴다. 조사기관별 편차가 크다
- 제품 적응증은 "최신 허가사항과 사용설명서를 확인하라"는 문구를 반드시 남긴다
- 모르는 것은 **모른다고 쓴다.** 추측을 사실처럼 쓰면 현장에서 사고가 난다
  (예: 세종스포츠 병용 제품은 녹취상 '다이렉스'로 들렸을 뿐 — 확인 필요로 표기)

모든 교육자료는 **사내 교육용 대외비**다. 문서 하단에 그 문구를 남기고,
외부 공유·SNS 게시를 하지 않는다. 환자 정보는 어떤 형태로도 넣지 않는다.
