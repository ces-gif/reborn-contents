# 트러블슈팅 · 클레임 대응

> 사내 자료가 스스로 지목한 2025년 과제가 **"클레임 발생 시 전문적인 대처 능력"**
> 이었다. 이 문서가 그 과제를 메우려고 만든 것이다.
>
> **굵은 원칙 하나**: 뎁포(Depot) 수리는 정품 절차와 정품 부품으로만 이루어져야
> 하며, **현장에서 임의 분해를 해서는 안 된다.** 우리가 현장에서 할 일은
> **"어디가 문제인지 좁혀서 정확히 접수하는 것"** 이다.
>
> 근거: Stryker 서비스 절차서 TSI10398 Rev.F / TSI10413 Rev.D 의 진단 로직을
> 현장용으로 재구성

---

## 1. 접수(Claim) 요령 — 이것만 지켜도 반은 해결된다

"No Problem Found"로 반송되는 케이스의 대부분은 아래 5가지가 빠져서 생긴다.

1. **증상을 정확한 단어로 적는다** — "화면이 이상하다"가 아니라
   "가로 줄이 간헐적으로 뜬다"
2. **교차 시험 결과를 함께 적는다** — 다른 카메라 헤드 / 다른 CCU 에서도 재현되는가
3. **에러코드와 소프트웨어 버전**을 캡처한다 (CCU LCD 우측 하단)
4. **케이블이 정품인지** 확인한다
5. **재현 사진·동영상**을 첨부한다

## 2. CCU 에러코드

| 코드 | 의미 | 원인 | 현장 1차 조치 | 뎁포 조치 |
|---|---|---|---|---|
| **E01** | Video Error | 메인보드 과전류 또는 영상처리 코어 통신 두절 | 전원 재기동 | 메인보드 교체 → 안 되면 디지털보드 |
| **E02** | Console Overheating | 팬 불량, 통풍 불량 | 전원 재기동, 통풍구·랙 공간 확인 | 팬 교체 → 디지털보드 |
| **E03** | Software Mismatch | 디지털/메인/프론트 보드 SW 버전 불일치 | 전원 재기동 | 버전 확인 후 SW 업그레이드 |
| **E05** | Unauthorized Component | 카메라 헤드 케이블의 인증칩 미검출 (비정품 케이블 포함) | 정품 케이블 여부 확인, 커넥터 청결·핀 상태 확인 | 디지털보드 → 트랜지션보드 |

> **E05 는 영업적으로 매우 중요한 코드다.**
> "정품이 아닌 케이블/부품"에서 자주 발생한다. 서비스 절차서도 서드파티
> 케이블이면 Stryker 정품으로 교체하도록 규정한다. 병원이 비정품 수리업체를 통해
> 케이블을 바꾼 경우 이 코드가 뜬다.
> **이때가 ProCare(정품 서비스 계약)의 가치를 설명할 최적의 순간이다** —
> 비인가 서비스는 성능·신뢰성 저하와 환자 위험으로 이어질 수 있다.

## 3. 카메라 헤드 — 증상별 원인 추적

| 증상 | 1차 확인 | 순차적 원인 (교체 순서) |
|---|---|---|
| 화이트밸런스가 안 됨 | QIP 절차대로 재시도 | 케이블 → 프리즘 |
| 색이 이상함 | 블랙밸런스 수행 | 블랙밸런스 → 케이블 → 프리즘 |
| 화면이 안 나옴 | 다른 정상 CCU 에 물려 확인 | 케이블 → 프리즘 |
| 검은 점 (콜드 픽셀) | 픽셀 결함 확인 | 프리즘 |
| 흰 점 (핫 픽셀) | 블랙밸런스 + 전원 재기동 후 재확인 | 프리즘 |
| 화면 번짐 (스미어) | 스미어 확인 | 케이블 → 프리즘 |
| 버튼 무반응 | 키패드 물리 손상 확인 | 키패드 → 4-button PCB → 내부 배선 |
| 센서 시프트 | 해상도·컬러바 확인 | 프리즘 |
| 프리즘 김서림 | **누수 검사 먼저** | 누수 있으면 해당 부품 교체 / 없으면 건조 면봉(소량 아세톤) 세정 |
| 헤드 전체 김서림 | 누수 검사 | 누수 없으면 일체형 커플러 내측 창 세정 |
| 간헐적 끊김 | 수 커넥터 핀 파손·굽음·부식 확인, 정상 콘솔로 교차 시험 | 케이블 → 프리즘 → KEL 케이블 |

### 누수(Leak) 및 외관

| 누수 위치 | 조치 |
|---|---|
| 전방–후방 인클로저 사이 | O-ring 점검 후 교체 → 그래도 새면 인클로저 교체 |
| 버튼 키패드 | 버튼 교체 |
| 전방 인클로저 창 | 전방 인클로저 교체 |
| 스트레인 릴리프 | 케이블 교체 |
| 케이블 절단부 | 케이블 교체 |
| 소커 캡 | 캡 조임·O-ring 확인 → 소커 캡 교체 |
| [외관] 키패드 분실·찢김 | 키패드 (필요 시 4-button 보드, 스냅링) 교체 |
| [외관] 커넥터 핀 파손·굽음·부식 | 케이블 교체 |
| [외관] 프리즘 파손 / 후방 인클로저 손상 | 프리즘 교체 / 외관 기준 검토 후 인클로저 교체 |

> **김서림이 보이면 즉시 사용 중단하고 누수 검사로 접수한다.**
> 부식된 커넥터는 수술 중 영상 끊김으로 이어진다.

## 4. CCU — 화질·기능 이상

| 증상 | 추적 순서 |
|---|---|
| 영상 없음 / 화면 안 나옴 | AC 퓨즈 → 메인보드 → 케이블·보드 결선 → 광절연 케이블 → 디지털보드 |
| 블랙 이미지 | 결선 → 광절연 케이블 → 트랜지션보드 → 디지털보드 → 메인보드 |
| 가로·세로·격자 선 | 디지털보드 → 트랜지션보드 → 메인보드 → 광절연 케이블 |
| 슈팅스타 (반짝이는 점) | 트랜지션보드 커넥터 부식 확인 → 트랜지션보드 → 디지털보드 |
| 영상에 물결 (waves) | 트랜지션보드 부식·손상 → 디지털보드 → 광절연 케이블 |
| 간헐적 라인 | 트랜지션보드(부식·너트 풀림·결선) → 케이블 흔들림 시험 → 디지털 → 메인 |
| 영상 정지 (프리즈) | 과별 프리셋 변경 시 반응 확인 → 디지털보드 → 메인보드 |
| 색상 오류 / 화면 잘림 / 줌·셔터 이상 | 디지털보드 → 메인보드 |
| 어둡고 노이즈 많은 영상 | 소프트웨어 업그레이드 → 디지털보드 → 메인보드 |
| 광원 토글 불가 | 트랜지션–디지털 데이터 케이블 → 디지털보드 → 메인보드 |
| 헤드 케이블 착탈이 뻑뻑함 | 트랜지션보드 교체 |
| 비프음 이상 | 프론트보드 |
| 무전원·간헐 전원 | 퓨즈 → AC 인렛 보드 → 파워서플라이 보드 |

| 보이는 것 | 가장 먼저 의심할 것 | 현장에서 할 일 |
|---|---|---|
| E01 | 메인보드 / 영상처리 코어 | 전원 재기동 후 접수 |
| E02 | 팬·통풍 | 통풍 확보, 재기동, 팬 소음 확인 |
| E03 | 보드 간 SW 버전 불일치 | LCD 우측 하단 버전 캡처 후 접수 |
| E05 | 비정품 케이블 / 인증칩 미검출 | 정품 케이블 여부, 커넥터 청결 |
| 화면 없음 | 케이블 → 프리즘 / CCU 퓨즈 | 다른 헤드·다른 CCU 로 교차 시험 |
| 흰 점·검은 점 | 프리즘 (픽셀 불량) | 블랙밸런스 후 재확인, 사진 첨부 |
| 간헐적 줄·끊김 | 커넥터 부식·핀 손상, 트랜지션보드 | 커넥터 육안 확인, 케이블 흔들림 시험 |

| 배터리 황색 점멸 | 잔량 2분 미만 | 예비 배터리 즉시 준비 |
| 배터리 황색 상시 | 완전 방전 또는 오류 | 교체 후 반복되면 접점·하우징 점검 |

## 6. 클레임 대응 표준 절차 (SOP)

| 단계 | 행동 | 금지 |
|---|---|---|
| 1. 접수 | 증상·발생 시점·재현 조건을 **고객의 말 그대로** 기록 | "별거 아닙니다"라는 즉답 |
| 2. 분리 | 장비 문제인지 소모품 문제인지 사용 문제인지 구분. 교차 시험 | 추측으로 원인 단정 |
| 3. 증거 | 에러코드, SW 버전, 사진·동영상, 로트번호 확보 | 증거 없이 구두 접수 |
| 4. 임시 조치 | **대차 장비 또는 대체 재고를 즉시 투입해 수술 일정을 보호** | 수리 완료까지 대기 |
| 5. 정식 접수 | 정품 서비스 채널로 접수 | 현장에서 임의 분해, 비인가 수리 |
| 6. 회신 | 원인·조치·재발 방지책을 **서면으로** 회신 | 구두 종결 |
| 7. 재발 방지 | 필요 시 재교육(인서비스). 특히 세척·멸균 절차 | 같은 클레임 반복 |

> **클레임은 위기가 아니라 기회다.**
> 클레임이 발생했다는 것은 그 병원이 우리 제품을 쓰고 있다는 뜻이다.
> 대응이 전문적이면 신뢰는 오히려 올라간다. 반대로 얼버무리면 그 순간 계정을 잃는다.
> **"모르겠습니다, 확인해서 오늘 중 회신드리겠습니다"가 어설픈 추측보다 언제나 낫다.**

## 7. 접수 대장

수리 건은 반드시 대장에 남긴다. 병원 독촉과 본사 지연 사이에서 방어할
**유일한 근거 자료**다.

```bash
# 접수 (본사에 함께 물어야 할 것이 자동으로 출력된다)
sumex repair open 서울적십자 "1788 CCU" "전원이 간헐적으로 꺼짐"

# 진행 갱신
sumex repair update --id R26-001 --set \
    status=본사확인중 \
    vendor_reply="부품 재고 확인 중" \
    eta=2026-09-05 \
    loaner="대차 1대 가능" \
    parts_in_stock=확인중

# 미결 건만
sumex repair list --open-only
```

상태값: `접수` `본사확인중` `부품대기` `수리중` `완료` `수리불가`

`sumex today` 가 **회신 없이 3일 이상 지난 건**을 자동으로 띄운다.
병원이 묻기 전에 먼저 연락하기 위한 장치다.

대장은 `data/private/repairs.json` 에 저장된다 (병원·장비 정보가 들어가므로 git 제외).
